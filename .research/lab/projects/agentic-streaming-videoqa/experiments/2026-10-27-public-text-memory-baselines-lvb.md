## 3. 2つの手法と、動かした条件

### 3.1 EventMemAgent [Wen+, ECCV 2026, arXiv 2602.15329]

| | 内容（公開コードのまま） |
|---|---|
| 記録 | 1fps で読む。今のイベントの平均フレームと新しいフレームの、グレースケールのヒストグラムの相関が 0.2 未満なら区切り（1イベント最低8枚）。短期記憶は最大32枚で、あふれたら一番古いイベントを、最大32枚の画像から凍結した Qwen3-VL-4B がキャプションにして長期記憶へ移す（前のイベントからの変化も1文書く）。1イベントが32枚を超えると、32枚をランダムに残す（reservoir sampling）。キャプションの temperature は 0.7 |
| 回答（公開のまま） | 強化学習で学習した EventMemAgent-8B（Qwen3-VL-8B）が、短期記憶の32枚を画像で見て、必要なら長期記憶を検索する（文での検索、または時刻の範囲。上位3件のキャプション・変化・最初の1枚が返る）。公開コードの評価（`eventmemagent.evaluation.batch`）をそのまま使った。最大10ターン、greedy |
| 回答（テキストだけ） | 長期記憶のキャプション（＋変化の文）を時刻付きの行にし、10/22 と同じ回答Agent（a3、Qwen3-VL-4B）に渡す。最後に短期記憶に残った枚にはキャプションがないので、同じ関数で1つキャプションを付けて足した（公開コードにはない追加） |

公開コードと違うところ:
- キャプション用の vLLM サーバは、A4000（16GB）に載せるため、`max-model-len` を 32768 → 10000、画像の上限を 64 → 33 にした。キャプションの1回の入力は32枚・約5,000 token なので、中身は変わらない。
- OCR と物体検出のサービスは立てていない。8B がこの2つを呼ぶと、エラーの文が返る（210問で OCR を5回呼んだ）。
- 記録を作るプロセスの一部が `accelerate` がないために埋め込みモデルを読み込めず、埋め込みのないイベントができた（公開コードは警告だけ出して続ける）。そのまま検索すると、キーワードの一致に落ちる。埋め込みはキャプションの文だけで決まるので、8B で答える前に、同じモデル・同じ設定で付け直した（`lvb/add_embeddings.py`）。

### 3.2 OneStreamer [Zeng+, arXiv 2610.01762]

| | 内容（公開コードのまま） |
|---|---|
| 記録 | OneStreamer-4B（Qwen3-VL-4B から学習）。4fps、直近128枚（32秒）を文脈にして、1秒ごとに `</Silence>`（何も書かない）、`</Observe>`（細部）、`</Summary>`（区切りの要約）のどれかを出す。OVOBench の memory の設定（`configs/ovobench.json`）をそのまま使った |
| 回答（公開のまま） | 記憶のテキスト（要約と細部、12,000 token まで）＋ 最後の16枚（1fps）を同じモデルに渡す |
| 回答（テキストだけ） | (a) 記憶のテキストだけを同じモデルに渡す。(b) 記憶を時刻付きの行にして、a3 に渡す |
| 対照 | 記憶なし ＋ 最後の16枚だけ |

公開コードと違うところ:
- 直近の枚を渡さないと、`engine.py` が入力の記録（`image_grid_thw`）を取るところで落ちるので、1行直した。
- TikTok 由来の動画の一部で、メタデータ上の最後のフレームが読めず、公開コードの読み込みが止まった。読める長さで1回だけやり直すようにした（`lvb/run_lvb.py`）。
