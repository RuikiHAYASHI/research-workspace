## 2. 条件

| | 内容 |
|---|---|
| 記録 | ① v6g（今の状態）、② v6g-lvb（v6g ＋ 質問の傾向の1節）。画像入力、区間あたり8枚、`Qwen/Qwen3-VL-4B-Instruct`、temperature 0、上限 4096 token |
| 区間（1枚の間隔） | 15: 8秒（1秒）、60: 20秒（2.5秒）、600: 40秒（5秒）、3600: 80秒（10秒） |
| 集約 | 段A v2 → 段B v9（既定の方法）。段Aでまとめる範囲・段Bの登場の区間は、もともと「その動画の1枚の間隔 × 枚数」で決まるので、間隔を変えてもコードの変更は要らなかった |
| 回答 | a3（同じモデル、テキストだけ）。入力は 記録だけ / 段A / 段A+段B の3通り。対照として、記録を渡さない「なし」も測る |
| 実行 | `scripts/run_batch.py`。GPU 3枚（RTX A4000）、長い動画のジョブから順に空いたGPUへ |

### サンプリング間隔の考え（計画の時点）

- 20秒・8枚（2.5秒に1枚）のままだと、記録は1区間あたり約21秒かかる。3600のグループ30本（10.6時間）は、1条件だけでGPU 1枚あたり約11時間になり、一晩で終わらない。
- 区間あたりの枚数は8枚のままにして、区間の長さだけを変える。プロンプト（`F1`〜`F8`）、1回の入力token（約8,500）、暴走しにくさを、どのグループでもそろえるため。違うのは「1枚の間隔」だけになる。
- 短い動画（8–15秒）は、2.5秒間隔では4〜6枚しか見られない。1秒間隔にすれば、細かく見られる。
- 長い動画は10秒間隔にすると、時間も行数も約1/4になる。そのかわり、10秒より短い出来事は見落とす。

### 3.3 パイロットで見えたこと（考察の材料）

1. **10秒間隔では、ほとんどの行が1枚だけの行になる。**
   - 例: `XYsCVqz3iug`（化学の解説、1489秒）は `[00:30.0-00:30.0]`、`[00:40.0-00:40.0]` … とほぼ全行が1枚。
   - 枚と枚の間が離れているので、毎回なにかが変わって見え、「同じ動作が続く」行がほとんどない。
   - そのため、段A（隣り合う同じ動作の行をまとめる）は7〜8%しか減らせない。**長い動画で集約できないのは、集約の規則の問題というより、間隔を広げたことの結果**だと考える。
2. **短い動作は、10秒間隔の記録から落ちる。**
   - `XYsCVqz3iug_0` の正解は「水色の矢印を机に置いた」。
   - `position` 10621 を29.97fpsで割ると約354秒。その時間帯の記録は `gestures with her hands while explaining a reaction mechanism`（05:40〜06:00）だけだった。
   - ただし、`position` ÷ fps が参照場面の秒だという前提は、あとで怪しいと分かった（4.5節の注意）。この例は「見落とし」の証拠としては弱い。
3. **15–60秒のグループで、記録Agentが暴走した区間が1つあった。**
   - `@movie.explained6-7275653401025826050_0`（縦長の映画解説）の3区間目で、`[F1-F1] EVENT: man in a blue uniform … lifts a person on a stretcher …` を121回くり返して上限に達した。v6g・v6g-lvb の両方。
   - 段Aがこの重複をまとめるので、60のグループの段Aの減り方（62%）は、ほぼこの1本による。
4. **質問と記録で、同じものの呼び方が違う。**
   - `@asianfoodrecipes-…_0` の質問は「豆腐にソースを塗る」。frameと画面の字幕（「add ketcup on the top」）から、実際はじゃがいもにケチャップを塗っている。記録（`brushes ketchup onto potato slices`）は正しい。
   - 回答Agentは「tofu が記録にない」と答えを断った。
5. **記録がなくても当たっていそうな問題がある。**
   - 3600のグループでは、正解の選択肢の語が参照場面の近くの記録に半分も出てこない問題でも、58%（12問中7問）当たった。誤答の選択肢が不自然で、選択肢だけで当てられている可能性がある。
   - そのため、記録を渡さない対照（「なし」）を本番の後に測ることにした。

| 3600 | 10秒 | 2.4秒 | 19% | 77%（13問） / 57%（77問） |

- 参照場面の時刻（`position` をフレーム番号とみなして秒にしたもの。この解釈は推論）の近くには、どのグループでもほぼ必ず行がある（1枚の間隔以内が99〜100%）。どの枚にも何かしら書くからである。
- 正解の選択肢の語が近くの行に出る割合は、2〜3割にとどまる。ただし、この指標は言い換え（tofu と potato、placed と puts など）を数えられない。短い動画では「語がない」問題の方がよく当たっており、正誤をうまく分けられていない。目安としてだけ使う。

## 5. 考察

### 5.1 どの長さでも動くか（今回の主目的）

- **動いた。** 8秒〜約1時間の動画で、記録 → 段A → 段B → 回答 が最後まで通った。記録の成功は240本中236本、回答の形式の失敗は1,248回答中4回。
- 一晩で動かすうえで止まった原因は、モデルではなく周りのコードだった:
  1. 質問IDの文字（`@`、`.`、先頭の `-`）。LongVideoBench の val には、TikTok由来の `@…` や、YouTubeのIDが `-` で始まる動画がある。
  2. 逐次ローダーの端の処理（下の5.4）。
  3. 実験のスクリプトの相対パス。
- 回答Agentの「答えを断る」出力は、プロンプト（a3）で 33/210 → 4/1,248 まで抑えられた。

### 5.2 記録は回答に役立っているか

- **役立っている。** どのグループでも、記録だけの正答率は記録なしより上（15: +43、60: +37、600: +10、3600: +26ポイント）。
- ただし、**記録なしでもチャンス（約21%）より上に当たる**（25〜43%）。選択肢だけで当たる問題がある。特に 600 のグループは記録なしで43%あり、記録の上乗せは +10ポイントにとどまる。
  - 600 のグループで記録の効きが小さい理由は、まだ分からない。1枚5秒の間隔で見落としが増えたのか、このグループの質問が選択肢だけで当てやすいのか、を分けて調べる必要がある（未確認）。
- **カテゴリ別では、O3O（物体の前後）だけが記録なしより悪い**（v6g 4/20、v6g-lvb 5/20、記録なし 7/20）。O3O は「ある物の直前・直後に現れた物」を聞く。記録Agentは動作（EVENT）を書くようにしているので、背景にある物の登場・退場はほとんど書かれない。記録の中の、場面に関係のない物の語に引っぱられて外している可能性がある（推測）。
- E2O（出来事 → 物体、2/16 → 12/16）、S2O（5/21 → 13〜16/21）、SOS（9/32 → 18/32）は、記録で大きく上がった。

### 5.3 集約（段A・段B）は回答に役立っているか

- **今回は、差が見えない。** 正答率の差は、どのグループも数ポイントで、問題数のばらつき（±10〜17ポイント）の中に入る。対応のある比較でも、片方だけ正解した数は、ほぼ左右同じ（例: 3600 の v6g の段A / 段A+段B は 5 / 1、v6g-lvb は 6 / 5）。
- 理由（考え）:
  1. **段Aで減る行が少ない（3〜7%）。** 回答Agentから見ると、記録だけと段Aの入力はほとんど同じ文字列になる。600 のグループでは、記録だけと段Aで正誤が変わった問題は0だった。
  2. **段BのIDは、今の回答のしかたでは使われていない。** 回答Agentは1回の呼び出しで全部を読む。IDが効くのは「同じ人が別の場面に再び出る」を聞く SOS などだが、ここも差が出ていない。短い動画では、段A+段Bが少し悪い（15: 64% → 61%、60: 70% → 63%）。`P04:` のような印が、小さいモデルにとってはノイズになっているのかもしれない（推測）。
- **林の懸念「長い動画で全然集約できていない」は、その通りだった。** ただし、原因は集約の規則より、サンプリングの間隔にあると考える。
  - 10秒間隔では、ほぼ全行が1枚だけの行（`[00:30.0-00:30.0]`）になる。枚と枚の間が離れているので、どの枚でも何かが変わって見え、「同じ動作が続く」行（段Aがまとめる相手）がほとんどない。
  - それでも、3600 のグループの記録は1本あたり約100行・約5,000 token で、1回の呼び出しに収まった。**今の規模では、集約しなくても回答Agentは全部を読める。** 集約が必要になるのは、もっと細かい間隔で記録したとき、またはもっと長い動画（数時間）である。
- 集約を役立てるには、「隣り合う同じ行をまとめる」以外の働きが必要だと考える。たとえば、
  - 時間スケールごとの要約（10/19 MTGの構想）を作り、質問に関係する時間帯だけを細かい記録で読む（分割統治）。
  - 段BのIDごとに「この人が出た時間帯」の一覧を作り、SOS・E3E のような複数の場面にまたがる質問で使う。

### 5.4 サンプリング間隔を変えたことについて

- **時間の面では狙い通り。** 600・3600 のグループは動画の長さの0.2〜0.5倍の時間で記録でき、オンラインで追いつける。一晩（GPU 3枚で約3時間）で2条件 × 120本（記録の合計 GPU 約8.5時間）を記録できた。
- **代わりに失ったもの:**
  - 10秒より短い出来事は見落とす（パイロットの `XYsCVqz3iug_0`「水色の矢印を机に置いた」）。
  - 3600 のグループの正答率（60%）は、15・60 のグループ（68〜70%）より低い。ただし、記録なしの対照も 25〜33% と 34% で違い、問題そのものの難しさも違うので、間隔だけの影響とは言えない。**同じ動画を、間隔だけ変えて比べる**必要がある（例: 3600 のグループの数本を 5秒・2.5秒で記録する）。
- **短い動画では、細かい間隔が遅さとローダーの失敗を生んだ。** 1秒間隔では、記録が動画の長さの約2倍の時間かかる（オンラインでは追いつかない）。また、5.5の端の問題は1秒間隔でだけ起きた。
- 次に試すなら、「区間あたりの枚数を固定して区間の長さを変える」のではなく、**1本あたりの枚数（または1分あたりの行数）をそろえる**比べ方もある。そうすると、グループ間で記録の量がそろい、集約の効き方を比べやすくなる。

### 5.5 失敗の原因のまとめ

| 失敗 | 件数 | 原因 | 対処 |
|---|--:|---|---|
| 記録が始まらない | パイロット16件、本番22件（重複あり） | 質問IDの `@`・`.`（Run IDの検査）、先頭の `-`（引数の解析） | 直した（`ea305cd`、`12d5a19`） |
| 記録が途中で止まる | 4件（2本 × 2条件） | 逐次ローダーの端の処理。データセットの動画長（13.01秒）より最後のフレーム（12.97秒）が早く、1秒間隔の最後の目標時刻 13.0秒に届かない | 未対処。ローダーで「最後のフレームより後の目標時刻は、最後のフレームを使う」ようにするのが候補（ローダーは別リポジトリなので、今夜は変えていない） |
| 記録の暴走 | 3区間 | 縦長の映画解説などで、同じ行を上限までくり返す | 段Aが重複をまとめるので、回答への害は小さい。時間（1本331秒）だけかかる。繰り返しを途中で止める仕組み（同じ行がN回続いたら打ち切る）が候補 |
| 回答を断る | a2 33/210、a3 4/1,248 | 記録に場面がない、または質問と記録で呼び方が違う（豆腐とじゃがいも） | a3 で抑えた |
| 範囲外の番号 `0` | a1 で数回 | 「どれでもない」の意味と考える | 文字の選択肢（a2）にした |

### 5.6 事前情報（v6g-lvb）の効果

- **差は見えない。** 記録だけの正答率は、4グループとも v6g と ±2ポイント以内。対応のある比較でも、片方だけ正解した数は左右ほぼ同じ（3600 で 6 / 7）。
- カテゴリ別では、S2O（13 → 16/21）と O2E（8 → 11/18）が少し上がり、E3E（23 → 20/35）と E2O（12 → 10/16）が少し下がった。物の色や持ち物を書かせた1文の効果と見ることもできるが、問題数が少なく、偶然の範囲である。
- 記録の行数は1〜7%増え、記録の時間は6〜16%増えた。
- 考え: 今回の事前情報は、「どんな質問が来るか」を言葉で伝えただけで、記録の形（1行1イベント、細部は1つだけ）は変えていない。4Bのモデルは、v6gの細かい規則（細部は1つ、場所は特徴2つまで）を優先し、追加の1節の効果が小さかったのかもしれない（推測）。予習を効かせるには、
  - O3O・S2O のように記録が弱いカテゴリに向けて、物の登場・退場を書く行（OBJECT など）を足すといった、**書く内容そのものを変える**予習が必要だと考える。
  - ただし、v5で物を書かせて暴走した経緯がある（[プロンプトの変遷](2026-10-21-record-prompt-evolution.md) 第18節）ので、上限を決めて試す。

### 5.7 次にやること（案。まだ決定ではない）

1. 同じ動画で、間隔だけを変えて比べる（3600 のグループの数本を 10秒・5秒・2.5秒）。間隔と精度の関係を、問題の難しさと分けて見る。
2. O3O・S2O 向けに、物の登場・退場を書く予習を試す。
3. 回答Agentに、時間スケールごとの要約と、関係する時間帯だけの細かい記録を渡す分割統治（集約を役立てる形）。
4. 逐次ローダーの端の処理を直す（最後のフレームより後の目標時刻）。
5. 記録の暴走を、同じ行のくり返しで打ち切る。
