# LongVideoQA Workbench（長時間動画QA実行環境）: 対象frame（フレーム）読取・観測台帳・可変長階層記憶の仕様

## 0. この仕様の状態

この文書は `draft`（下書き）である。実装、branch（作業枝）の作成、commit（変更記録）の作成、push（リモート反映）、Qwen（視覚言語モデル）による実動画評価は許可しない。実装着手には、この文書を `approved`（承認済み）へ更新する明示承認が必要である。

## 2. 背景と問題定義

現行のWorkBench（ブラウザ実行環境）は、600秒・32frame（フレーム）の実行でも、全デコードframe（フレーム）をRGB（赤・緑・青）化する連続読取経路を使用している。また、観測用のQwen（視覚言語モデル）指示文が選択肢を含むため、複数frame（フレーム）を渡しても1から4frame程度の場面説明へ収束しやすい。

さらに、window（時間窓）ごとの結果を最終回答へ渡す情報集約の境界が成果物上で明確でない。ここでは、別のAgent（独立した自律実行体）を増やすのではなく、同じモデル呼出しを役割ごとに分離し、全観測の証跡と要約物語を別々に保存する。

## 3. 目的

1. 利用者が既存の全RGB（赤・緑・青）読取と対象frame（フレーム）専用読取を明示的に選べるようにする。
2. 観測段階では選択肢による回答を禁止し、入力された全frame（フレーム）に対する構造化観測を必須にする。
3. 情報集約段階で、時系列の物語を可変長に保ちつつ、文脈量が上限を超えるときだけ古い詳細を章へ圧縮する。
4. 全frame（フレーム）観測を捨てずに成果物へ残し、最終回答がどの証跡・物語に基づくか追跡可能にする。
5. 既存の実行設定、既存の全RGB（赤・緑・青）経路、既に修正済みのサムネイル表示の挙動を回帰させない。

## 4. 非目標

- sequential_loader（連続動画ローダー）内部の実装変更は行わない。必要な公開 `target_frame_stream`（対象frame専用ストリーム）は、関連するローダー仕様の承認・実装後にのみ利用する。
- 観測時に選択肢から正解を選ばせないことは、最終回答時に選択肢を参照しないことを意味しない。
- 物語の固定長化、観測台帳の削除、根拠のない圧縮率・速度・精度の主張は行わない。
- 字幕を利用するモード、ランダムseek（任意位置へのジャンプ）、複数動画の並列実行は本仕様の対象外である。
- 既存のブラウザ表示不具合修正をこの仕様の変更として再実装しない。対象frame（フレーム）モード追加後の回帰テストだけを行う。

## 6. 実行設定と公開UI（利用者画面）

### 6.1 読取mode（動作モード）

実行設定へ `reader_mode`（読取モード）を追加する。

```yaml
reader_mode: full_rgb
```

`full_rgb`（既存の全frame RGB化）は既定値であり、既存recipe（実行レシピ）を変更しない。新しい `target_only`（対象frame専用）は、`sequential_loader.target_frame_stream`（連続動画ローダーの対象frame専用公開ストリーム）を利用できる場合だけ選択可能にする。

`target_only`（対象frame専用）で必要な設定は、`duration_seconds`（動画長）、`window_seconds`（時間窓長）、`frames_per_window`（窓あたりframe数）である。初期検証用recipe（実行レシピ）は600秒・32frame（フレーム）とし、既存recipe（実行レシピ）を上書きせず別ファイルとして追加する。

ローダーが新しい公開API（公開呼出し口）を提供していない環境で `target_only`（対象frame専用）が選ばれた場合、WorkBench（ブラウザ実行環境）は既存経路へ黙ってfallback（代替実行）してはならない。不足しているローダーの版と必要な公開要素を示して実行開始前に失敗する。

### 6.2 ブラウザ画面

ブラウザ画面には、読取mode（動作モード）の選択肢、解決済み設定、各window（時間窓）の選択frame数、各成果物へのリンクを表示する。開始後に設定値を変更できない現行契約を維持する。

実行ごとに一意の `run_id`（実行識別子）を用い、サムネイルURL（画像URL）へその識別子または表示改訂値を反映する。これにより、2回目の実行後に1回目のframe（フレーム）がブラウザキャッシュにより黒く見える回帰を防ぐ。これは既存修正を維持する受入条件であり、重複実装の指示ではない。

## 7. 三層の情報モデル

情報集約は別Agent（独立した自律実行体）ではなく、同じQwen（視覚言語モデル）を三つの役割で順に呼ぶ。各呼出しの入力・出力は成果物として保存し、役割混同を避ける。

| 層 | 内容 | 保存方針 | 最終回答への役割 |
| --- | --- | --- | --- |
| 観測台帳 | 全入力frame（フレーム）ごとの構造化観測 | 削除せず追記 | 検証可能な一次証跡 |
| 窓イベント | 同じwindow（時間窓）内の出来事・順序・変化 | 削除せず追記 | 物語作成の素材 |
| 物語記憶 | 複数window（時間窓）を接続した時間順の説明 | 可変長、必要時のみ章へ圧縮 | 最終推論の主な文脈 |

観測台帳と窓イベントは `memory.jsonl`（一行ごとのJSON記録）へ追記する。物語記憶、章、最終回答への参照は `memory.json`（統合JSON記録）へ保存する。各レコードには `run_id`（実行識別子）、`window_index`（窓番号）、`frame_index`（frame番号）、実際の表示時刻、目標時刻を含める。

## 8. 観測段階のprompt（指示文）と検証

### 8.1 観測prompt（指示文）の原則

観測prompt（指示文）には質問本文とframe（フレーム）を渡すが、選択肢、正解番号、選択肢へ対応する語句を渡さない。モデルには回答や推測を求めず、各入力frame（フレーム）について必ず次の項目を返させる。

| 項目 | 内容 |
| --- | --- |
| `frame_index`（frame番号） | 入力で渡した番号。 |
| `timestamp_seconds`（実際の表示時刻） | 入力で渡した時刻をそのまま返す。 |
| `scene`（場面） | 可視の人物、物体、場所、行為、画面内文字を簡潔に記述する。 |
| `question_relevance`（質問との関連） | `high`（高い）、`medium`（中程度）、`low`（低い）、`uncertain`（不明）のいずれか。 |
| `confidence`（確信度） | 0から1の数値。 |
| `uncertainty`（不確実性） | 見えない、判別不能、時間順不明などを空文字でなく明記する。 |

観測出力は次のJSON（構造化テキスト形式）オブジェクトのみとし、コードフェンス、前置き、選択肢回答を禁止する。

```json
{
  "observations": [
    {
      "frame_index": 0,
      "timestamp_seconds": 0.0,
      "scene": "...",
      "question_relevance": "medium",
      "confidence": 0.72,
      "uncertainty": "..."
    }
  ]
}
```

このJSON（構造化テキスト形式）の `observations`（観測列）は、入力したframe（フレーム）数と同数で、各 `frame_index`（frame番号）が一意かつ入力順に対応しなければならない。

### 8.2 観測の失敗処理

JSON（構造化テキスト形式）が構文不正、frame（フレーム）が不足・重複、時刻が入力メタデータと不一致、選択肢回答を含む場合、そのwindow（時間窓）を「観測検証失敗」として停止する。静かに不足frame（フレーム）を捨てたり、前window（時間窓）の観測で補ったりしてはならない。

失敗時にも、生のモデル出力、入力frame一覧、検証エラーを成果物へ保存する。再試行の有無と回数は設定値として明示し、初期値は0回とする。

## 9. 窓イベントと物語記憶

### 9.1 窓イベントの生成

窓イベントのprompt（指示文）は、当該window（時間窓）の検証済み観測台帳だけを入力とする。質問への最終回答や選択肢選択を禁止し、次を生成する。

- 時刻順の出来事
- 画面上の変化と因果・順序の候補
- 質問に関係する証拠と不確実性
- 各出来事が参照する `frame_index`（frame番号）列

出力は構造化JSON（構造化テキスト形式）で、各イベントに証拠frame（フレーム）参照を一つ以上持たせる。事実、推定、不明を区別する。

### 9.2 可変長の物語

物語記憶は固定文字数に切り詰めない。新しいwindow（時間窓）が到着するたび、既存の章、既存の詳細物語、当該window（時間窓）のイベントを入力にし、前の出来事から自然に接続された時間順の物語へ更新する。

物語には必ず時間範囲、根拠イベント参照、不確実性を含める。新window（時間窓）が前の内容と無関係な場合も、無理に因果関係を作らず、時間上の新しい節として接続する。

### 9.3 上限到達時だけの階層圧縮

設定 `memory_budget_tokens`（記憶に使う最大token数）を追加する。初期の対象frame専用recipe（実行レシピ）では6,000token（モデル文脈量の単位）とする。この値は精度主張ではなく、実験で変更・記録する設定値である。

更新後の物語入力が上限を超える場合だけ、最も古い連続した詳細window（時間窓）群を一つのchapter（章）へ圧縮する。章には次を必須とする。

- 対象時間範囲
- 出来事の時間順
- 保持すべき人物、物、場所、状態変化
- 各主張へのイベントID（識別子）とframe（フレーム）参照
- 不確実性と、圧縮した詳細window（時間窓）番号

圧縮済みの生観測と窓イベントは削除しない。`memory.jsonl`（一行ごとのJSON記録）に完全に残し、章は参照用の索引を持つだけとする。新しいwindow（時間窓）は、直近の詳細物語と必要な古い章へ接続して更新する。

`memory_budget_tokens`（記憶に使う最大token数）は、Qwen用tokenizer（字句分割器）で計測する。モデル接続層は物語入力のtoken数を報告する小さな公開メソッドを持ち、テスト用の偽モデルは決定的な簡易計数器を使う。実モデルと偽モデルの数値を同一視しない。

## 10. 最終回答段階

最終回答のprompt（指示文）には、質問、選択肢、物語記憶、章、関連する窓イベント、必要時の観測台帳参照を渡す。観測段階と異なり、ここで初めて選択肢を提示し、回答・根拠・不確実性を求める。

最終成果物には、選択した回答だけでなく、参照した `event_id`（イベント識別子）、`frame_index`（frame番号）、時刻、物語版を保存する。これにより、どのwindow（時間窓）のどの観測が最終結論へ影響したかをたどれる。

## 11. 設定、成果物、再現性

実行開始時に、解決済みの設定へ少なくとも次を保存する。

- `reader_mode`（読取モード）
- `duration_seconds`（動画長）
- `window_seconds`（時間窓長）
- `frames_per_window`（窓あたりframe数）
- 観測、イベント、物語、最終回答ごとの生成設定
- `memory_budget_tokens`（記憶に使う最大token数）
- ローダーとWorkBench（ブラウザ実行環境）の版識別子

成果物には、入力frame（フレーム）の実際の時刻・目標時刻・番号、各段階の生出力、検証済み構造化出力、検証エラー、圧縮前後の物語版、章と参照ID（識別子）を残す。既存の実行成果物の形式は、`reader_mode`（読取モード）が `full_rgb`（既存の全frame RGB化）の場合に読み取り可能でなければならない。

## 12. 実装を承認後に行う段階

各Step（主要段階）は専用branch（作業枝）で行う。次のStep（主要段階）のbranch（作業枝）は、直前Step（主要段階）の全micro step（小段階）が検証済みである最終commit（変更記録）から作成する。各micro step（小段階）は、表に記した検証が通った直後に、表に記した一つのcommit（変更記録）だけを作成する。未検証の複数micro step（小段階）を一つのcommit（変更記録）へまとめてはならない。

| micro step（小段階） | 変更内容 | commit（変更記録）の題名 | commit（変更記録）前の検証 |
| --- | --- | --- | --- |

branch（作業枝）は `feat/observation-ledger-validation`（観測台帳と検証の作業枝）とする。基点はStep B1（主要段階）の最終commit（変更記録）である。

### Step B3（主要段階）: 窓イベントと可変長物語を追加する

branch（作業枝）は `feat/window-events-narrative-memory`（窓イベントと物語記憶の作業枝）とする。基点はStep B2（主要段階）の最終commit（変更記録）である。

### Step B4（主要段階）: 最終回答と回帰条件を固定する

branch（作業枝）は `feat/final-answer-evidence-trace`（最終回答と根拠追跡の作業枝）とする。基点はStep B3（主要段階）の最終commit（変更記録）である。

## 13. 受入条件

| 観点 | 合格条件 |
| --- | --- |
| 既存互換 | `full_rgb`（既存の全frame RGB化）を指定・省略した実行が、既存の設定と成果物形式で動く。 |
| 接続分離 | `target_only`（対象frame専用）は公開ローダー経由でのみ動き、ローダー不足時に黙って既存経路へ切り替わらない。 |
| 観測完全性 | 各window（時間窓）で入力frame数と観測数が一致し、frame番号・時刻が一意かつ入力と一致する。 |
| 選択肢分離 | 観測prompt（指示文）に選択肢が入らず、観測出力に選択肢回答が含まれた場合は検証失敗となる。 |
| 証跡保持 | 全観測と窓イベントが実行終了後も成果物に残り、章圧縮後も参照可能である。 |
| 可変長 | 上限未満では詳細物語を圧縮せず、上限超過時のみ連続した最古範囲を章にする。 |
| 追跡可能性 | 最終回答からイベント、frame（フレーム）、時刻、物語版へ逆引きできる。 |
| ブラウザ回帰 | 2回目の実行後にも1回目のサムネイルが黒化せず、両実行の画像を確認できる。 |
