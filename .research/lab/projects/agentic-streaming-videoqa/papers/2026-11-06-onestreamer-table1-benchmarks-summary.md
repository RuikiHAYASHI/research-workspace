## 1. 表1 を一文で

[論文] **OneStreamer-4B は、ストリーミング動画の 8 つのベンチマークのすべてで、比べた手法の中で一番高い。** 元にした Qwen3-VL-4B（表1 の最下段の上の行）からも、全部のベンチで上がっている。

表の読み方:

- 行 = 手法（上半分は古い手法で、多くは「−」= その論文が報告していない。下の 7 行が最近の強い手法で、8 つ全部に値がある）
- 列 = 8 つのベンチマーク。**左の 4 つが「Perception & Memory」、右の 4 つが「Proactive Response」**
- Size = パラメータ数。OneStreamer は 4B で、8B・11B の手法にも勝っている、というのが論文の見せ方
- 比べる相手として一番大事な行は 2 つ:
  - **Qwen3-VL (base) 4B**: OneStreamer の学習前のモデル。「学習で何が上がったか」を見る相手
  - **MOSS-VL-Realtime 11B**: 多くのベンチで 2 番手。「最強の他手法」を見る相手

## 2. 左右の分け方：「聞かれたら答える」か「いつ答えるかも自分で決める」か

[AI] 表1 の左右は、**問題の形と採点の仕方**で分けると分かりやすい。

| | 左: Perception & Memory | 右: Proactive Response |
|---|---|---|
| 質問が来るタイミング | ある時刻に質問が来る | 動画の最初（または途中）に指示が来る |
| モデルが見られる映像 | 質問の時刻までの映像だけ（未来は見えない） | 同じ。動画が流れ続ける |
| モデルがすること | その時点で 1 回答える | 黙って見続け、「今だ」と思った時刻に応答する（何回でも） |
| 答えの形 | ほぼ 4 択（一部 2 択・数・Yes/No） | 自由な文章（または「今」という合図だけ） |
| 採点 | 正答率（%） | **答えた時刻**が合っているか ＋ 中身が合っているか（中身は LLM が採点するベンチが多い） |

[論文] 図2 の言い方では、左は Memory QA（過去を聞く）と Perception QA（今を聞く）、右は Proactive QA（先に聞いておき、証拠が出たら答える）。

## 4. 表1 から言えること（論文の主張）と、説明するときの注意

### 言えること

1. **8 つ全部で 1 位**（[論文]）。元の Qwen3-VL-4B からの上がり幅は、左が +13.3・+5.1・+11.4・+13.7、右が +14.4・+7.2・+12.2・+0.46（ViSpeak は 0〜5 点）
2. **11B の MOSS-VL-Realtime にも全部で勝つ**（[論文]）。差は左が +1.9・+4.0・+13.1・+7.4、右が +1.5・+3.9・+3.1・+0.39
3. [AI] 上がり幅が小さいのは StreamingBench（+5.1）。元の Qwen3-VL-4B がもともと 81.8 と高く、「今を聞く」問題は元のモデルでも解けている。上がり幅が大きいのは、過去や未来・タイミングが関わるベンチ（OVO-Bench・ODV-Bench・ProactiveVideoQA・OVO-Timing）

### 注意（聞かれたら答えられるように）

1. **比べ方が手法ごとに違う**（[論文] 付録 D）。他手法の値は「その論文が報告した値」か、「公開された重みを、元の設定と OneStreamer の設定の両方で評価して高い方」（付録の表で † が付いたもの）。OneStreamer はベンチごとに入力の与え方（fps・窓の大きさ・記憶を使うか）を変えている
2. **「−」が多い**。上半分の古い手法は 8 つのうち 1〜5 個しか値がない。「全部で 1 位」は、主に下の 7 行（4〜11B の最近の手法）との比較
3. **右の 3 つ（ProactiveVideoQA・OmniMMI・ViSpeak）は LLM（Qwen3-235B）が中身を採点する**。採点する LLM の版や設定で点が変わりうる
4. **OmniMMI の 5 タスクのうち、自分から応答するのは PA だけ**（[データ]）。ほかの 4 つは時刻ごとに質問が来て答える形。表1 では全体を右（Proactive）に入れている
5. **OVO-Bench の Forward と OVO-Timing は同じ 3 タスク**だが、採点が違う。OVO-Bench（左）は時刻ごとに質問して中身を採点、OVO-Timing（右）は応答した時刻だけを採点
6. **記憶（PHCM）の効果が直接効くのは左の 2 つ（OVO-Bench・StreamingBench）だけ**。ほかのベンチの上がり幅は、学習データ（OneStreamer-1M）と学習のやり方（PSTL）の効果と考えるのが自然（[AI]。論文は表16 で、記憶を書く学習が OVBench・ODV-Bench も少し上げたと主張している）
7. StreamingBench の問題数は論文 2,498、公開されている注釈は 2,500。どの 2 問を外したかは書かれていない

## 6. 30 秒で説明するなら（台本の案）

> 表1 は、OneStreamer-4B をストリーミング動画の 8 つのベンチマークで評価した結果です。左の 4 つは、動画の途中で質問されて、その時点までの映像だけで答える問題で、過去のことを聞くもの、今のことを聞くものがあります。右の 4 つは、先に指示だけもらっておいて、答えるべき場面が来たら自分から応答する問題で、何を答えたかに加えて、いつ答えたかも採点されます。OneStreamer は 4B で、8 つすべてで比べた手法の中で一番高く、元の Qwen3-VL-4B から 5〜14 点、11B の MOSS-VL-Realtime からも 1.5〜13 点上がっています。ただ、他手法の値は報告値と再評価が混ざっていて、右の 3 つは LLM が採点しているので、その点は割り引いて見る必要があります。私の再現では、LLM 採点の要らない ODV-Bench と OVO-Timing は論文とほぼ同じ値が出ています。

## 7. OVO-Bench Overall（72.1）の中身（2026-11-06 追記）

### 計算のしかた

[論文] 表8 の説明: 「各区分の平均はサブタスクの重みなし平均。Overall は 3 区分の平均の重みなし平均」。[実験] 公式コード（`Proactive_Eval/OneStreamer/src/onestreamer/metrics.py` の `aggregate`）も同じで、3 区分のどれかのサブタスクが欠けると Overall を出さない。

```text
Overall = ( Real-Time の平均 + Backward の平均 + Forward の平均 ) / 3
          ( 81.4             + 77.9            + 56.9           ) / 3 = 72.1
```

| 区分 | 何を聞くか | サブタスク（問題数） | OneStreamer | Qwen3-VL-4B | MOSS 11B |
|---|---|---|---|---|---|
| Real-Time | 今の画面 | OCR 文字 149・ACR 動作 109・ATR 属性 116・STU 位置関係 178・FPD 次の行動 101・OJR 物体 184（計 837） | 81.4 | 73.2 | 75.9 |
| Backward | 過去の出来事 | EPM 出来事の記憶 297・ASI 動作の順序 148・HLD 映っていないことを聞く 186（計 631） | **77.9** | 53.8 | 72.6 |
| Forward | 時点ごとの数・状態 | REC 回数 698・SSR 指定の手順を今やっているか 629・CRR 手がかりの出現 240（計 1,567） | 56.9 | 49.4 | **62.1** |
| Overall | | 3,035 | **72.1** | 58.8 | 70.2 |

問題数は作り直した注釈の dry-run での数（[実験]）。

注意:
- 区分ごとに同じ重みなので、631 問の Backward と 1,567 問の Forward が Overall に同じだけ効く。サブタスクも同じ重みで、HLD（186 問）1 つが Backward の 1/3、Overall の 1/9 を占める
- 公式コードは OVO-Bench を「記憶あり（memory）」と「直近 16 枚だけ（recent16）」の 2 設定で回す（`run_script/recipes.py`）。表1 の 72.1 は記憶あり。表2 の FIFO（70.1）が recent16 に当たる

### 伸びがどこから来ているか

[実験] 元の Qwen3-VL-4B からの +13.3 点は、ほとんどが Backward（+24.1）から来ている。Real-Time は +8.2、Forward は +7.5。Forward は MOSS（62.1）に負けている。

[実験] Backward の中でも HLD が 41.9 → 99.5（+57.6）と飛び抜けている。EPM は 59.9 → 62.6、ASI は 58.1 → 71.6。
- [データ] HLD の 186 問は、正解がすべて「Unable to answer」（作り直した注釈。選択肢は OVO-Bench の元の注釈のまま）
- [実験] 再現の途中結果（記憶あり、2026-11-06 02:10 時点、Backward 568/631 問）: HLD 186 問中 185 問で「Unable to answer」を選んだ（99.5%、論文と同じ値）。EPM 63.3（297 問すべて、論文 62.6）、ASI 70.6（85/148 問、論文 71.6）
- [データ] 「Unable to answer」という選択肢は、Backward では HLD の問題にしか出てこない（EPM・ASI の選択肢には 0 問）
- [AI] なので、HLD の 99.5 は「映っていないことに気づけた」というより、「Unable to answer という選択肢があれば選ぶ」ふるまいでも出せる値。HLD 以外の問題に「Unable to answer」を混ぜて選ぶかどうかを確かめないと、どちらかは区別できない（未検証）。学習データ（OneStreamer-1M）に答えられない質問が入っているかは未確認
- [AI] 仮に HLD を Qwen3-VL-4B と同じ 41.9 にすると、Backward は約 58.7、Overall は約 65.7 になる。Overall の伸び +13.3 のうち、約 6.4 点が HLD 1 つから来ている計算（表8 の値からの単純な計算）

### 記憶（PHCM）の効果が出ているところ

[論文] 表2 では、記憶ありとなし（FIFO）の差は Overall で +2.0（70.1 → 72.1）。内訳は ASI +8.1（63.5 → 71.6）、EPM +0.6（62.0 → 62.6）、Real-Time +0.5（80.9 → 81.4）。[AI] 記憶の効果は主に ASI（動作の順序）に出ていて、Overall の伸び +13.3 のうち記憶で説明できるのは 2.0 点ほど。残りは学習そのもの（データと PSTL）の効果と読める

### 記憶づくりは質問の時刻を知っているか（2026-11-06、公式コードで確認）

[実験] 記憶あり（memory）の設定では、問題ごとに動画の先頭から**質問の時刻（`end`）まで**記憶を作る（`caption_optimized.py` の `run_caption_pass`）。モデルが受け取るのは 1 秒ごとの映像だけで、質問の文も時刻も入力されない。ただし、質問の時刻に着いたとき、直前の出力が `</Observe>` だった場合だけ、`<STREAM_END>` という合図を送って、まとめの `</Summary>` を 1 つ書かせる（`finalize_caption_boundary`、設定 `flush_summary: true`）。

[実験] 再現の途中結果（Backward 575 問）: この合図が送られたのは 165 問（29%）。記憶の中の `</Summary>` 949 個のうち 165 個（17%）が、この合図で書かれたもの。

[AI] 質問が来た時点でまとめを書かせるだけなので、未来の映像や質問の中身は漏れていない。ただし、論文の §3・付録 A.2 の「質問とは関係なく記録を書き溜める」という説明より、少しだけ質問の到着に合わせた作りになっている。論文には、この合図のことは書かれていない（付録 C.2・D を確認した範囲）。
