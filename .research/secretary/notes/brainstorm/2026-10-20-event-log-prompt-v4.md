# 記録プロンプト v4

前の版: [記録プロンプトv3](2026-10-20-event-log-prompt-v3.md)。実装: [記録Agent Workbench spec](../../../lab/projects/agentic-streaming-videoqa/specs/2026-10-20-pre-study-record-workbench-spec.md)。本文は新リポジトリの `prompts/record/image/v4/prompt.en.txt`（commit `c6edac6`）。

## きっかけ（林の指示、2026-10-20）

- v3で約3分の動画（`66dwcQ1Y048_0`）を記録すると、TEXTが大量発生した。コードで同じ行を消すのは綺麗ではないので、プロンプトで直す。
- あわせて「時間の問題」も解決する（実行時間と、時刻がframeと合わない問題の両方を対象にした）。

## v3で起きていたこと（実データで確認）

| 問題 | 内容 |
| --- | --- |
| TEXTのループ | 2区間で同じTEXT行を繰り返し（`"BROADWAY HOLLYWOOD"` を136回など）、max_new_tokens 4096に達して各265秒 |
| 1枚目だけを書く | 8枚とも場面が違う区間でも、区間全体 `[140.0-160.0]` で1枚目の場面だけを書いた |
| 時刻のずれ | 時刻をframeの時刻でなく区間の終わりで書いた（416行中372行が不一致） |
| 画像と時刻の対応 | 画像はラベルなしで並び、時刻一覧は文章の後ろにあるだけだったので、モデルはどの画像が何秒か分からなかった（区間2で、路地を20秒・渦巻きの男性を30秒と書いた。実際は逆の順） |

## 試した案（問題の区間だけで比較）

| 案 | 変更 | 結果 |
| --- | --- | --- |
| v4a | frameを順に見る、カットごとにSCENE、TEXTは5行まで・小さな画面文字は書かない、同じ行を書かない、10〜40行 | TEXTのループは止まった。画像と時刻の対応はずれたまま |
| （入力の変更） | 各画像の直前に「frame k (t s):」のラベルを置く（コードの変更、commit `c6d1d4c`） | 以後の案すべての前提 |
| v4b | ラベルを使うよう指示、区間の終わりの時刻をプロンプトから外す、同じ場面はまとめる | 時刻はすべてframeと一致。ただし1枚だけのものを `[30.0-32.5]` と書く・1枚ずれる区間が残る |
| v4c | 時刻の書き方を具体例で強調 | かえって悪化（場面の始まりが1枚前にずれる） |
| v4d | 範囲をframe番号 `[F3-F5]` で書かせる | **画像と記録の対応が全frameで正しくなった**。ただし `[F2]` `[F3]` と1枚ずつ書く |
| v4e（採用） | v4dに「続く枚は1つの範囲にまとめる」の具体例を追加 | まとめられる区間が出た（`[F1-F3]`）。一部はまだ1枚ずつ |

AIの考え: 4Bのモデルは、秒数でframeを正確に指すのが苦手。画像の直前のラベルと同じ番号で指させると、対応を取りやすい。秒への変換はコード（解析処理）で行う。

## 残る課題（未対応）

- EVENTが少ない（224行中10行）。場面の多い動画では、SCENE・ENTITY・OBJECTで行数を使い切っている可能性がある。
- 1行に複数の人や物をまとめて書くことがある（「1行に1人」の指示が守られていない）。
- 同じ場面を1枚ずつ書く区間がある（まとめの指示が一部効いていない）。
- TEXTの上限（5行）を1区間だけ超えた（6行）。
- 評価は1本の動画（ショートカットの多いVlog）だけ。動きの多い動画・長い動画では未確認。
