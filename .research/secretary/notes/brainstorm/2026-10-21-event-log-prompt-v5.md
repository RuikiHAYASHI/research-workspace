## 指標と基準

すべて自動で数えた（スクリプトは scratchpad、ローカルのみ）。

| 指標 | 基準 |
| --- | --- |
| max_new_tokensに達した区間、時刻の不一致、解析できない行 | 0 |
| 同じ範囲・同じ本文の重複行（ループ） | なし |
| 1行に複数の人や物（「;」でつないだENTITY/OBJECT） | 0 |
| まとめ損ね（同じTYPE・同じ本文の1枚だけの行が隣り合う） | 各動画3以下 |
| 人が写っている場面のうちEVENTがない場面 | 1割程度以下 |
| TEXT | ループしない（違う文字を1回ずつ） |

EVENTは当初「全行に占める割合15%以上」を基準にしたが、1人が話し続けるニュースでは割合が上がらないのが正しいので、「人が写っている場面にEVENTがあるか」に変えた。

## 試した案（3本で比較）

| 案 | 変更 | 結果 |
| --- | --- | --- |
| v4 | （基準） | Vlog EVENT 4.5%・まとめ損ね14、料理 同じ行8回・まとめ損ね41、ニュース TEXT 7行 |
| v5a | 先に場面の一覧を書く2段階、人と物は1行に1つ、場面ごとに最低1つのEVENT | Vlog EVENT 15.5%・まとめ損ね1。料理のまとめ損ね16 |
| v5b | 誤りと正しい例の組（同じ物を1枚ずつ、2人を1行、none、ロゴ） | 1行に複数の人0、まとめ損ね0/4/0。Vlogで動作をENTITYに書く |
| v5c | ENTITYは見た目だけ・動作はEVENT、動作が変わっても同じ場所なら同じ場面 | 料理は全基準を満たした。TEXTが増える（コラージュの字幕） |
| v5d | 各ENTITYの直後にEVENT、行数の上限を50に | EVENTの抜けは減ったが、OBJECTのループ（185回）が起き悪化 |
| v5e | OBJECTは1場面5行まで、行数を10〜40に戻す | 3本ともループなし・基準をほぼ満たす。ただし追加の2本で、スマホ設定画面のTEXTが297行・クレジットが19行 |
| v5f | 「何もない」行の禁止を言い換え | OBJECT・CHANGEのループが再発し悪化 |
| v5g（採用） | v5e＋文字の多い画面（メニュー・設定・一覧・文書・クレジット）はタイトルだけ | クレジットは19→6行。3本で最良（下表）。スマホの色一覧の画面はまだ暴走 |

AIの考え:
- 否定の例に「none」という語そのものを書くと、かえって真似されることがある。
- 行数の上限を緩めたり、指示を少し変えたりするだけで、ループが出たり消えたりした（v5d、v5f）。ループはtemperature 0の貪欲生成の性質によるもので、プロンプトだけでは、初めて見る種類の画面まで確実には防げないと考える。

## 残る課題と、相談中のこと

- **文字がぎっしり並んだスマホ画面の暴走**（日常Vlogの1区間でTEXT 297行）。プロンプトでは止まらなかった。
  - 生成設定 `repetition_penalty` 1.05 で止まることを確認した（同区間のTEXT 297→7行、上限到達1→0、日常Vlog全体 569→446秒。最初のVlogは悪化なし）。行を消す後処理ではない。
  - 注意点: 前に出た言葉も繰り返しにくくなるので、「同じ人は同じ呼び方」が守られにくくなるおそれがある。
  - **採用するかを林に確認中**（2026-10-21）。
- 何もないことを書いた行（`TEXT: none` など）が、まれに残る（料理で2行）。
- 1区間のTEXTが8行を少し超えることがある（実際に画面にある字幕・項目で、ループではない）。
